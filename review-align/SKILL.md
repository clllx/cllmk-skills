# 复盘分析与对齐

## 职责

读取每日原始记录和计划中心，客观分析进展、卡点、偏差和下一步行动。输出简洁、可执行的总结。不要修改原始记录；需要调整计划中心时只提出建议，除非用户明确要求执行修改。

## 默认文件

- 计划中心：`/opt/daily/user/PLANNING_CENTER.md`
- 每日原始记录：`/opt/daily/user/YYYY-MM-DD 周X.md`
- 日总结：`/opt/daily/user/reviews/daily/YYYY-MM-DD 周X.md`
- 周总结：`/opt/daily/user/reviews/weekly/YYYY-MM-DD 周报.md`
- 月总结：`/opt/daily/user/reviews/monthly/YYYY-MM 月报.md`

优先使用用户明确指定的路径。写入前读取已有文件；重复执行时局部更新对应总结，不重复追加相同内容。

只把 `/opt/daily/user/` 根目录下名称严格匹配 `YYYY-MM-DD 周X.md` 的文件视为每日原始记录。不要把 `PLANNING_CENTER.md`、归档文件或 `reviews/` 下的总结误当作原始记录。

## 默认执行规则

用户没有明确指定周期时：

1. 生成当天日总结。
2. 当天是周一时，读取上一个自然周周一至周日的原始记录，并额外生成周总结。周总结文件使用当天日期命名。
3. 当天是当月最后一天时，读取当月原始记录，并额外生成月总结。

用户明确要求周报、月报或指定日期时，按用户要求执行，不受当天日期限制。

## 分析原则

- 只根据计划中心和实际存在的原始记录分析，不虚构事实。
- 把每日原始记录作为事实来源。已有日总结和周总结只用于辅助聚合，不得覆盖原始记录中的事实。
- 区分事实、推断和建议。信息不足时明确标记。
- 优先关联计划 ID；没有 ID 时使用简短计划名称。
- 评价保持客观，指出偏差但不说教。
- 明日或下周期行动要具体、可立即执行、数量克制。
- 无法定量时使用定性描述，不编造完成率。

## 日总结

读取当天原始记录和计划中心，写入：

```markdown
# 每日复盘 | YYYY-MM-DD 周X

## 今日进展
- 事项 | 对齐计划：P-YYYYMMDD-NN / 计划名称 / 未关联

## 卡点与偏差
- 事实：用户记录的情况
- 判断：与计划的偏差或待确认信息

## 明日行动
- [ ] 最先执行的具体动作 | 对齐计划：P-YYYYMMDD-NN / 计划名称

## 罗盘
- 方向：当前最重要的目标
- 聚焦：明天最优先的 1 至 3 项
- 风险：最需要控制的问题
- 建议：需要拆分、调整或归档的计划；没有则写“暂无”
```

## 周总结

周一自动生成，或在用户明确要求时生成。读取目标自然周内存在的原始记录、已有日总结和计划中心，写入：

```markdown
# 周度复盘 | YYYY-MM-DD 至 YYYY-MM-DD

## 本周进展
- 与计划一致的主要产出

## 重复卡点
- 多次出现的问题或风险

## 计划对齐
- 方向：与长期、年度或月度计划的吻合情况
- 偏差：需要修正的事项

## 下周行动
- [ ] 最重要的行动，最多 3 项

## 罗盘
- 聚焦：下周核心方向
- 风险：需要提前处理的问题
- 建议：是否需要修改计划中心
```

样本不足时明确列出缺失日期，不据此下强结论。

## 月总结

月底自动生成，或在用户明确要求时生成。读取目标月份内存在的原始记录、已有日总结、已有周总结和计划中心，写入：

```markdown
# 月度复盘 | YYYY-MM

## 本月进展
- 与月度、年度和长期计划相关的主要产出

## 里程碑
- 已完成、未完成或部分完成的关键事项

## 系统性卡点
- 重复出现的问题及其影响

## 下月行动
- [ ] 最重要的行动，最多 3 项

## 罗盘
- 方向：下月核心方向
- 风险：需要持续控制的问题
- 建议：需要新增、拆分、调整或归档的计划
```

## 执行流程

1. 获取当前日期、星期和月底判断，或解析用户指定日期。
2. 读取计划中心和目标周期内存在的记录。
3. 生成对应总结，确保每条判断能追溯到记录或计划。
4. 创建缺失目录并写入总结文件。
5. 向用户展示总结正文，并汇报保存路径。
6. 缺少原始记录、目录不可写或计划中心不存在时，明确说明缺口并继续完成仍可完成的部分。

## 与计划罗盘的边界

- 用户只想检查计划是否完整、聚焦或需要调整时，使用计划中心技能。
- 用户想结合每日执行记录判断偏差、生成日周月总结或复盘罗盘时，使用本技能。
