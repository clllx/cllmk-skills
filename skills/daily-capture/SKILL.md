# 每日信息采集

## 职责边界

只收集、整理、展示和保存用户提供的信息。不要分析计划对齐情况，不评价表现，不推测原因，不生成日总结、周总结或月总结。需要分析时交给独立复盘分析技能。

## 默认文件

- 每日原始记录：`/opt/daily/user/YYYY-MM-DD 周X.md`

优先使用用户明确指定的路径。每日文件已存在时，读取后合并新增信息，不覆盖用户未要求修改的内容；合并时删除完全相同的重复条目。

## 启动方式

- `/daily`：询问用户今天做了什么、遇到什么问题、明天准备做什么。
- `/daily xxxx`：把 `xxxx` 视为第一段原始记录，直接整理并追问缺失信息。

从系统时间获取当前日期和星期。用户明确要求补录时，使用用户指定日期。

## 采集流程

1. 收集用户今天做到的事情、没做到的事情或卡点、明日安排，以及可选备注。
2. 用户输入内容不完整时，进行简洁追问。每轮最多追问 3 个事实问题。
3. 在用户明确输入 `OK`、`done`、`好了`、`没有了`、`结束` 或含义明确的同类表达前，不要写入文件。
4. 收到结束信号后，将多轮输入整理为结构化 Markdown。
5. 向用户展示完整结构化数据，同时写入当天文件。
6. 写入后汇报文件路径。不要追加分析或建议，也不要自动调用复盘分析技能。

用户仅输入 `/daily` 时，使用简洁开场：

```text
请告诉我你今天做到了什么、没做到什么或有什么卡点，以及明天准备做什么？
```

追问时可使用：

```text
收到，已记录。
[最多 3 个需要补充的事实问题]
如果已经记录完毕，请发送“OK”、“done”或“好了”。
```

## 文件格式

保持标题顺序稳定，便于后续分析技能读取。没有相关信息时填写 `- 暂无记录`。

```markdown
# 每日原始记录 | YYYY-MM-DD 周X

## 今日做到
- 用户确认的事实

## 今日没做到或卡点
- 用户确认的事实

## 明日安排
- [ ] 用户确认的安排

## 备注
- 用户补充的信息
```

只做轻量格式化，例如拆分列表、去除明显重复和修正错别字。不要把模糊描述擅自改写成用户没有确认的承诺。

## 补录与修改

- 用户要求补录其他日期时，写入目标日期文件。
- 用户要求修改记录时，读取原文件后局部更新。
- 用户要求删除信息时，只删除明确指定的条目。
- 遇到目录不存在时创建目录；遇到权限不足时请求授权或询问替代路径。
